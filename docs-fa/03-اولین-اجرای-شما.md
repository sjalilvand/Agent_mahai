# آموزش ۰۳ — اولین اجرای شما

در این آموزش، رابط وب dsh را راه می‌اندازید، مدل را وصل می‌کنید، فضای کاری را انتخاب می‌کنید و اولین وظیفه واقعی را به عامل می‌سپارید. فرض این آموزش این است که نصب را طبق [آموزش ۰۲](02-نصب-گام-به-گام.md) انجام داده‌اید.

## راه‌اندازی رابط وب

```sh
npx @deepseek-ai/dsh web
```

سرور روی `http://127.0.0.1:3080` بالا می‌آید و مرورگر به‌صورت خودکار باز می‌شود. چند نکته درباره رفتار این دستور:

- اگر در حال اتصال از طریق SSH به سرور باشید (مثلاً یک سرور ابری خارج از ایران که برای دور زدن محدودیت‌ها اجاره کرده‌اید)، آدرس به‌صورت خودکار باز نمی‌شود؛ چون آدرس فورواردشده را کلاینت SSH شما تعیین می‌کند و فقط URL در خروجی چاپ می‌شود. با `-L 3080:127.0.0.1:3080` پورت را فوروارد کنید و در مرورگر خودتان باز کنید.
- `--no-open` سرور را بدون باز کردن مرورگر اجرا می‌کند — مناسب سرورهای بدون محیط گرافیکی.
- `dsh web --help` فهرست کامل گزینه‌های این اپ را نشان می‌دهد.

## پروفایل‌ها — دستور پخت اجرای شما

هر بار که dsh را اجرا می‌کنید، در واقع یک «پروفایل» بوت می‌شود. پروفایل، پشته‌ای مرتب از پلاگین‌ها است که تعیین می‌کند مدل چه ابزارهایی ببیند و با چه مجوزهایی کار کند. پروفایل‌های آماده اصلی:

| پروفایل | دستور | کاربرد |
|---|---|---|
| `web` | `dsh web` | رابط وب کامل — پیشنهادی برای شروع |
| `tui` | `dsh tui` | رابط متنی در ترمینال |
| `headless` | `dsh headless "وظیفه"` | یک وظیفه، یک پاسخ، خروج — مناسب اسکریپت و CI |
| `acp` | `dsh acp` | سرویس پروتکل ACP برای اتصال ادیتورها و کلاینت‌های اتوماسیون |
| `sdk` | `dsh sdk` | بستر برنامه‌نویسی برای ساخت اپلیکیشن عامل خودتان |

پروفایل‌های کاربر شما در `$DSH_HOME/profiles` ساخته می‌شوند. اگر پروفایلی خراب شد یا می‌خواهید نسخه تمیز از قالب رسمی بسازید:

```sh
dsh rescue --from-default-profile web
```

و برای دیدن ترکیب نهایی پلاگین‌های پروفایل فعال:

```sh
dsh --profile web --dump-config
```

## اتصال مدل — کارت DeepSeek

برای اینکه عامل کار کند به یک مدل زبانی نیاز دارد. راه اصلی پروژه، API رسمی DeepSeek است:

1. اگر هنوز حساب ندارید، در [platform.deepseek.com](https://platform.deepseek.com/) ثبت‌نام کنید و از بخش API Keys یک کلید بسازید (ثبت‌نام نیازمند شماره تلفن یا ایمیل و شارژ اولیه حساب است).
2. در رابط وب به **Settings → Models** بروید.
3. کارت **DeepSeek** یک فیلد کلید API دارد؛ کلید را وارد و ذخیره کنید. بدون نیاز به ری‌استارت، مسیر مدل بلافاصله فعال می‌شود.
4. فهرست مدل‌ها (مثل `deepseek-chat` و `deepseek-reasoner`) از خود API دیپ‌سیک بارگذاری می‌شود و تقریباً هر ده دقیقه در پس‌زمینه به‌روز می‌ماند؛ اگر بارگذاری ممکن نشد، فهرست داخلی به‌عنوان جایگزین استفاده می‌شود.

نکات امنیتی مهم درباره کلیدها:

- کلیدها فقط نوشتنی (write-only) هستند؛ بعد از ذخیره، رابط هیچ‌وقت مقدار واقعی را نمایش نمی‌دهد، فقط یک توصیف پوشانده‌شده می‌بیند.
- کلید در فایل `$DSH_HOME/.credentials.yaml` ذخیره می‌شود و تنظیمات فقط ارجاعی به آن نگه می‌دارند. این فایل را هرگز عمومی نکنید.
- توجه: پرداخت هزینه API دیپ‌سیک از ایران به‌راحتی ممکن نیست؛ بخش «اتصال از طریق دروازه واسط» در پایین همین آموزش را ببینید.

## اتصال مدل — ارائه‌دهنده شخصی یا دروازه واسط (مهم برای کاربران ایران)

چون دسترسی مستقیم به API دیپ‌سیک از داخل ایران معمولاً به‌دلیل تحریم‌ها و مسائل پرداخت دشوار است، dsh دو راه جایگزین عملی می‌دهد:

### راه اول: ارائه‌دهنده‌های آماده

در **Settings → Models** روی **Add model provider** کلیک کنید. فهرست ارائه‌دهنده‌هایی که dsh به‌صورت آماده می‌شناسد نمایش داده می‌شود (شناسه‌هایی مثل `anthropic`، `openai`، `moonshotai` برای Kimi و `zai` برای GLM). کلید API ارائه‌دهنده را وارد و ذخیره کنید؛ آدرس پایه، پروتکل و فهرست مدل‌ها به‌صورت خودکار تنظیم می‌شوند.

اگر فیلد کلید را خالی بگذارید، dsh به اعتبارنامه ذخیره‌شده یا متغیرهای محیطیِ معرفی‌شده در همان کارت مراجعه می‌کند؛ راهنمای سبز یعنی متغیر محیطی شناسایی شده و راهنمای زرد یعنی چیزی پیدا نشده و باید کلید را دستی وارد کنید.

### راه دوم: API سفارشی (دروازه واسط)

اگر از یک سرویس واسط ایرانی یا یک سرور واسط خارج از ایران استفاده می‌کنید (سرویس‌هایی که با پرداخت ریالی، دسترسی OpenAI-compatible به مدل‌های مختلف می‌دهند)، کارت را روی **Custom model API** بگذارید و این فیلدها را پر کنید:

- **Provider ID**: یک شناسه حروف‌کوچک لاتین (مثل `ir-relay`) — دائمی است و بعداً قابل تغییر نیست؛ نشست‌ها و ارجاع اعتبارنامه‌ها با همین شناسه کار می‌کنند.
- **Base URL**: آدرس دروازه واسط (مثل `https://relay.example.com/v1`).
- **API protocol**: باید دقیقاً پروتکلی باشد که دروازه شما حرف می‌زند — سه گزینه موجود است: `openai-completions` (رایج‌ترین)، `openai-responses` و `anthropic-messages`.
- **Credential** و حداقل یک مدل.

در دکمه **Fetch available models** می‌توانید فهرست مدل‌های واقعی دروازه را بگیرید و مدل‌های دلخواه را تیک بزنید. اگر این قابلیت کار نکرد، شناسه مدل را دستی اضافه کنید؛ همان‌قدر خوب کار می‌کند.

مثال تنظیم دستی همان چیز در فایل پروفایل (`$DSH_HOME/profiles/web/cordis.patch.yml`) — این فایل همان چیزی است که صفحه تنظیمات می‌نویسد و می‌توانید مستقیم ویرایشش کنید:

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-relay:
        apiKeyEnv: RELAY_API_KEY
        api: openai-completions
        baseURL: https://relay.example.com/v1
        models:
          - id: deepseek-chat
          - id: deepseek-reasoner
```

متغیر `RELAY_API_KEY` را هم در محیط یا فایل اعتبارنامه تعریف کنید. تنظیمات در درخواست بعدی اعمال می‌شود و نیازی به ری‌استارت نیست.

⚠️ **یادآوری امنیتی:** کلید API خود را در هیچ مخزن عمومی (از جمله همین مخزن (ماه‌ای))، اسکرین‌شات یا فایل‌های اشتراکی قرار ندهید. اگر ناخواسته کلیدی را افشا کردید، بلافاصله از پنل ارائه‌دهنده باطلش کنید.

## انتخاب فضای کاری (Workspace)

رابط وب تا وقتی یک فضای کاری انتخاب نشود، کامپوزر پیام غیرفعال است. دکمه **Choose workspace** را بزنید و پوشه پروژه‌ای را که می‌خواهید عامل در آن کار کند انتخاب کنید. دقت کنید: پروسه dsh از مسیر فراخوانی، مکان پیش‌فرض فایل‌سیستم را می‌گیرد؛ پس اگر می‌خواهید روی پروژه خاصی کار کنید، بهتر است `dsh web` را از داخل همان پوشه اجرا کنید.

## اولین وظیفه واقعی

یک نشست جدید باز کنید و این پیام را بفرستید (مثال مستندات رسمی):

> Summarize this repository and identify its main packages.

عامل اجازه دارد فایل‌ها را بخواند و ویرایش کند، دستور اجرا کند، کار را تفویض کند و برنامه نگه دارد. هر عملیاتی که طبق سیاست مجوز فعال نیاز به تأیید داشته باشد، رابط وب قبل از اجرا از شما می‌پرسد — این فرصت مرور شماست؛ عادت کنید هر تأیید را جدی بگیرید.

چند پیشنهاد برای اولین تجربه:

- «این پوشه را تحلیل کن و توضیح بده چه پروژه‌ای است» — تست ابزار خواندن فایل.
- «یک اسکریپت پایتون بنویس که نام فایل‌های این پوشه را در یک CSV بریزد و اجرایش کن» — تست نوشتن کد و اجرای bash.
- «یک صفحه HTML ساده با تم فارسی بساز» — تست deliverables و ارائه خروجی.

## حالت‌های دیگر اجرا

- **headless برای اسکریپت‌نویسی:** `npx @deepseek-ai/dsh headless "خلاصه‌ای از این پروژه بنویس"` — پاسخ نهایی در stdout چاپ می‌شود و رخدادهای اجرا در stderr. با `--json` خروجی رخدادها به‌صورت JSON-Lines می‌آید که برای اتوماسیون عالی است. با `--session-id` می‌توانید یک نشست ذخیره‌شده را ادامه دهید.
- **TUI:** اگر ترمینال‌محور کار می‌کنید، `dsh tui` رابط متنی کامل با همین ابزارها می‌دهد.
- **ACP برای ادیتورها:** با `dsh acp` می‌توانید ادیتورهای پشتیبان پروتکل Agent Client Protocol را به عامل وصل کنید.

## به‌روزرسانی dsh

چون پروژه در پیش‌نمایش توسعه‌دهنده است و سریع تغییر می‌کند، به‌روز نگه‌داشتن مهم است:

```sh
# کش npx را پاک کنید تا نسخه جدید گرفته شود
npx clear-npx-cache   # در صورت وجود، یا:
npm cache clean --force
npx @deepseek-ai/dsh@latest web

# یا در نصب سراسری:
npm update -g @deepseek-ai/dsh
```

اگر از سورس این مخزن استفاده می‌کنید، پوشه `dsh/` را با آخرین نسخه مخزن رسمی جایگزین کنید (روش دقیق در [آموزش ۱۱ — گردش کار گیت](11-گردش-کار-حرفه‌ای-گیت.md) توضیح داده شده).
