# آموزش ۰۶ — ساخت پلاگین اختصاصی

این آموزش از مقدماتی تا یک پلاگین کامل بومی ایرانی جلو می‌رود. منبع اصلی این بخش، [راهنمای توسعه رسمی](../dsh/docs/user/develop/basic/index.md) در سورس پروژه است و مثال‌ها را برای کاربر فارسی‌زبان با کامنت فارسی بازنویسی کرده‌ایم. پیش‌نیاز: اجرای dsh از سورس طبق [آموزش ۰۲ گام ۴](02-نصب-گام-به-گام.md)، چون پلاگین‌نویسی با `--patch` روی اجرای محلی انجام می‌شود.

## مفاهیم پایه: پلاگین، باندل، پروفایل

سه مفهوم را از هم جدا کنید — اشتباه‌گرفتن آن‌ها رایج‌ترین خطای تازه‌کارهاست:

- **پلاگین**: یک ماژول جاوااسکریپت/تایپ‌اسکریپت با تابع `apply` که به زمین Cordis وصل می‌شود و قابلیت اضافه می‌کند (ابزار، سرویس، رابط).
- **باندل (Bundle)**: بسته npm‌ای که یک «لایه پیکربندی» حمل می‌کند — در `package.json` خود کلید `dsh.bundle` دارد و می‌گوید «چه چیزی به سیستم اضافه می‌کنم؟» باندل چیزی است که شما می‌نویسید و توزیع می‌کنید.
- **پروفایل (Profile)**: پوشه‌ای در `$DSH_HOME/profiles/<name>` که ترکیب قابل اجرا را توصیف می‌کند — در مانیفست خود `dsh.profile` دارد و می‌گوید «کدام باندل‌ها به چه ترتیبی؟». پروفایل چیزی است که کاربر با `dsh --profile <name>` بوت می‌کند.

هیچ چیزی هم‌زمان باندل و پروفایل نیست. ضمناً بسته‌ای که `dsh.bundle` ندارد هم نصب می‌شود اما فقط به‌عنوان وابستگی ساده — برای کتابخانه‌هایی که پلاگین‌ها import می‌کنند.

## پلاگین «سلام دنیا»

یک پوشه بسازید و سه فایل را ایجاد کنید:

**`hello-plugin/package.json`**

```json
{
  "name": "dsh-hello-plugin",
  "version": "0.1.0",
  "type": "module",
  "main": "index.js",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

**`hello-plugin/index.js`**

```js
// نقطه ورود پلاگین — Cordis این تابع را صدا می‌زند
export const name = 'hello-plugin'

export function apply() {
  console.log('[hello-plugin] پلاگین بارگذاری شد!')
}
```

**`hello-plugin/cordis.patch.yml`**

```yaml
# لایه پیکربندی: سطر پلاگین را به ترکیب «اضافه» می‌کند
- insert:
    - id: hello
      name: dsh-hello-plugin   # ارجاع به نام بسته — Node خودش کد را پیدا می‌کند
```

و اجرا با لایه اضافی:

```sh
pnpm dsh web --patch ./hello-plugin/cordis.patch.yml
```

پیام «پلاگین بارگذاری شد!» در کنسول سرور ظاهر می‌شود. `--patch` قابل تکرار است و لایه‌ها بعد از لایه پروفایل اعمال می‌شوند؛ همچنین `patch` می‌تواند فهرست مرتبی از چند فایل باشد.

## اولین ابزار واقعی: `greet`

حالا کد را به یک ابزار مدل‌محور ارتقا دهید — `hello-plugin/src/my-plugin.ts` (در نسخه تایپ‌اسکریپتی با اجرای از سورس):

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'
// تزریق وابستگی: Cordis صبر می‌کند تا رجیستری ابزار آماده شود
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'به یک نفر سلام می‌کند.',
    parameters: {
      // از روی همین پارامترها، اعتبارسنجی ورودی خودکار ساخته می‌شود
      name: { type: 'string', required: true, description: 'نام فرد مورد سلام' },
    },
    output: {
      schema: { type: 'string' },
      // خروجی متعارف به محتوای رو‌به‌روی مدل تبدیل می‌شود
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `سلام، ${args.name}!`
    },
  }))
}
```

سه نکته کلیدی از این نمونه:

1. **`inject`** مکانیزم تزریق وابستگی Cordis است؛ با `['tools']` اعلام می‌کنیم «به رجیستری ابزار نیاز دارم» — Cordis ترتیب بارگذاری را تضمین می‌کند.
2. **`defineTool`** از روی `parameters` ورودی‌ها را infer و validate می‌کند — خطای شِما را خودش می‌گیرد.
3. **جدایی خروجی متعارف و رندر**: `execute` مقدار خام برمی‌گرداند (`output.schema`) و `output.render` آن را به محتوای مدل‌محور تبدیل می‌کند — همین جدایی باعث می‌شود یک ابزار همزمان برای مدل، UI وب و لاگ نسخه‌های درست داشته باشد.

اجرای مجدد و تست در رابط وب:

```sh
pnpm dsh web --patch ./hello-plugin/cordis.patch.yml
```

در مکالمه بگویید: `Use the greet tool to greet Sara.` — مدل ابزار `greet` را صدا می‌زند و «سلام، Sara!» می‌گیرد.

## پلاگین بومی: «تقویم شمسی» 🇮🇷

حالا چیزی می‌سازیم که واقعاً بومی‌سازی است: ابزار تبدیل تاریخ میلادی↔شمسی. عامل شما با این ابزار می‌تواند «سه شنبه چندمه است؟» یا «یادم بنداز ۲۵ اسفند کدام روز میلادی است» را دقیق جواب دهد.

**`jalali-plugin/package.json`**

```json
{
  "name": "dsh-jalali-plugin",
  "version": "0.1.0",
  "type": "module",
  "main": "index.js",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

**`jalali-plugin/index.js`** — الگوریتم تبدیل استاندارد جلالی به‌صورت مستقل و بدون وابستگی:

```js
// پلاگین تقویم شمسی — ابزار بومی‌سازی‌شده برای عامل‌های ایرانی
export const name = 'jalali-tool'

// ---- هسته تبدیل: الگوریتم جلالی→میلادی و برعکس ----
function div(a, b) { return ~~(a / b) }
function jalCal(jy) {
  // محاسبه روزهای استثنا تقویم جلالی (بر اساس جدول استاندارد)
  const breaks = [-61, 9, 38, 199, 426, 686, 756, 818, 1111, 1181, 1210, 1635, 2060, 2097, 2192, 2262, 2324, 2394, 2456, 3178]
  let bl = breaks.length, gy = jy + 621, leapJ = -14, jp = breaks[0], jm, jump = 0, leap, n, i
  for (i = 1; i < bl; i += 1) {
    jm = breaks[i]; jump = jm - jp
    if (jy < jm) break
    leapJ = leapJ + div(jump, 33) * 8 + div(jump % 33, 4)
    jp = jm
  }
  n = jy - jp
  leapJ = leapJ + div(n, 33) * 8 + div(n % 33 + 3, 4)
  if (jump % 33 === 4 && jump - n === 4) leapJ += 1
  const leapG = div(gy, 4) - div((div(gy, 100) + 1) * 3, 4) - 150
  const march = 20 + leapJ - leapG
  if (jump - n < 6) n = n - jump + div(jump + 4, 33) * 33
  leap = ((((n + 1) % 33) - 1) % 4)
  if (leap === -1) leap = 4
  return { leap, gy, march }
}
function g2d(gy, gm, gd) {
  let d = div((gy + div(gm - 8, 6) + 100100) * 1461, 4) + div(153 * ((gm + 9) % 12) + 2, 5) + gd - 34840408
  d = d - div(div(gy + 100100 + div(gm - 8, 6), 100) * 3, 4) + 752
  return d
}
function d2g(jdn) {
  let j = 4 * jdn + 139361631
  j = j + div(div(4 * jdn + 183187720, 146097) * 3, 4) * 4 - 3908
  const i = div((j % 1461) / 4, 1) * 5 + 308
  const gd = div((i % 153) / 5, 1) + 1
  const gm = (~~(i / 153)) % 12 + 1
  const gy = div(j, 1461) - 100100 + div(8 - gm, 6)
  return { gy, gm, gd }
}
function jalaaliToGregorian(jy, jm, jd) {
  const r = jalCal(jy)
  return d2g(g2d(r.gy, 3, r.march) + (jm - 1) * 31 - div(jm, 7) * (jm - 7) + jd - 1)
}
function gregorianToJalali(gy, gm, gd) {
  const d2 = g2d(gy, gm, gd)
  let jy = gy - 621
  const r = jalCal(jy)
  const jdn1f = g2d(gy, 3, r.march)
  let k = d2 - jdn1f
  if (k >= 0) {
    if (k <= 185) return { jy, jm: 1 + div(k, 31), jd: (k % 31) + 1 }
    k -= 186
  } else {
    jy -= 1; k += 179
    if (r.leap === 1) k += 1
  }
  return { jy, jm: 7 + div(k, 30), jd: (k % 30) + 1 }
}

// ---- تعریف پلاگین ----
export const inject = ['tools']

const MONTHS = ['فروردین','اردیبهشت','خرداد','تیر','مرداد','شهریور','مهر','آبان','آذر','دی','بهمن','اسفند']

export function apply(ctx) {
  ctx.tools.register({
    name: 'date_convert',
    description: 'تبدیل تاریخ بین تقویم شمسی (جلالی) و میلادی. برای پرسش‌های تاریخ ایران استفاده کن.',
    parameters: {
      direction: { type: 'string', required: true, enum: ['jalali-to-gregorian', 'gregorian-to-jalali'], description: 'جهت تبدیل' },
      year:  { type: 'number', required: true, description: 'سال' },
      month: { type: 'number', required: true, description: 'ماه (۱ تا ۱۲)' },
      day:   { type: 'number', required: true, description: 'روز ماه' },
    },
    async execute(args) {
      if (args.direction === 'jalali-to-gregorian') {
        const g = jalaaliToGregorian(args.year, args.month, args.day)
        return {
          gregorian: `${g.gy}-${String(g.gm).padStart(2, '0')}-${String(g.gd).padStart(2, '0')}`,
          persian: `${args.year} ${MONTHS[args.month - 1]} ${args.day}`,
        }
      }
      const j = gregorianToJalali(args.year, args.month, args.day)
      return {
        jalali: `${j.jy}-${String(j.jm).padStart(2, '0')}-${String(j.jd).padStart(2, '0')}`,
        persian: `${j.jy} ${MONTHS[j.jm - 1]} ${j.jd}`,
      }
    },
    // رندر متنی برای مدل — ساده و بدون ابهام
    output: { schema: { type: 'object' }, render: (_a, v) => [{ type: 'text', text: JSON.stringify(v) }] },
  })
}
```

**`jalali-plugin/cordis.patch.yml`**

```yaml
- insert:
    - id: jalali
      name: dsh-jalali-plugin
```

اجرای محلی:

```sh
pnpm dsh web --patch ./jalali-plugin/cordis.patch.yml
```

و در مکالمه: «۲۵ اسفند ۱۴۰۴ چه روزی از سال میلادی است؟» — عامل از ابزار `date_convert` استفاده می‌کند و جواب دقیق می‌گیرد. همین نمونه کامل و آماده تست در پوشه [`examples/jalali-plugin`](../examples/jalali-plugin/) این مخزن موجود است.

💡 **ایده‌های دیگر بومی‌سازی**: ابزار تبدیل اعداد فارسی/انگلیسی، ابزار تاریخچه تعطیلات رسمی ایران، ابزار نرخ ارز از منابع داخلی، ابزار رشته‌های فارسی (نیم‌فاصله و ی/ک عربی)، ابزار «کد ملی» برای اعتبارسنجی. هر ابزار دقیق و کم‌دامنه، ارزشمندتر از یک ابزار همه‌کاره است.

## پیکربندی پلاگین (جایگزین‌پذیر کردن مقادیر)

برای آنکه مقادیر (مثلاً منطقه زمانی پیش‌فرض) از پیکربندی بیاید نه از کد، پلاگین‌ها می‌توانند یک آبجکت پیکربندی از Cordis بگیرند — الگوی رسمی در [مستند پیکربندی پلاگین](../dsh/docs/user/develop/basic/config.md) توضیح دارد که چطور فیلد `config` در سطر پلاگینِ patch به ورودی تابع `apply` تزریق می‌شود و مقادیر پیش‌فرض چطور اعلام می‌شوند. قانون طلایی: **override پیکربندی Cordis، کل آبجکت ورودی را جایگزین می‌کند** — پس هنگام ویرایش `cordis.patch.yml` موجود، بقیه فیلدها را حفظ کنید.

## لایه‌بندی قابلیت‌ها (سبک حرفه‌ای)

وقتی پلاگین شما بزرگ شد، [الگوی لایه‌بندی قابلیت](../dsh/docs/user/develop/practice/index.md) رسمی سه بسته به هم می‌دهد:

- **Service Definition**: قرارداد (interface) قابلیت + ثبت در زمینه — بدون پیاده‌سازی.
- **Service Provider**: پیاده‌سازی واقعی که قرارداد را پر می‌کند (قابل تعویض).
- **Consumer**: پلاگین‌هایی که فقط به قرارداد تکیه می‌کنند.

این همان الگویی است که در خود dsh استفاده شده (مثلاً `ctx.shell` را چند executor مختلف می‌پرکنند: bash محلی، pwsh ویندوز، PTY ماندگار). مزیت: کاربران می‌توانند پیاده‌سازی شما را بدون دست زدن به مصرف‌کننده‌ها عوض کنند — فلسفه «همه‌چیز پلاگین است» در اوج خودش.

## چک‌لیست کیفیت پلاگین

- نام ابزارها کوتاه، معنادار و یکتا (سبک کاتالوگ رسمی: snake_case)
- `description` دقیق و جهت‌دهنده — مدل با همین متن تصمیم می‌گیرد ابزار شما را صدا بزند یا نه
- پارامترهای required حداقلی؛ هرچی کمتر، احتمال خطای مدل کمتر
- خروجی ساختاریافته + رندر متنی تمیز
- خطاها را به‌شکل پیام قابل‌فهم برگردانید نه crash
- اعلام `engines.dsh` در `package.json` برای سازگاری نسخه (مثلاً `"engines": { "dsh": ">=0.2.0 <0.3.0" }`)
