# آموزش ۰۹ — رفع مشکلات رایج در ایران

این آموزش پرکاربردترین بخش برای کاربران داخل ایران است: مشکلات شبکه، تحریم، میرورها، پروکسی و خطاهای مرتبط. ساختار هر بخش: علامت → علت → درمان.

## ۱) خطای 403 یا Timeout هنگام `npx @deepseek-ai/dsh web`

**علامت:** دانلود بسته گیر می‌کند، پیام‌های `ETIMEDOUT`، `ECONNRESET` یا `403 Forbidden` از registry.npmjs.org.

**علت:** رجیستری رسمی npm برای IPهای ایران گاهی محدودیت می‌گذارد یا مسیر شبکه ناپایدار است.

**درمان:** میرور ایرانی را تنظیم کنید:

```sh
npm config set registry https://registry.npmjs.ir/
npm ping          # باید pong برگرداند
npx @deepseek-ai/dsh web
```

اگر میرور در دسترس نبود یا بسته‌ای را نداشت، از اسکریپت آماده استفاده کنید: `bash scripts/setup-iran.sh` (میرور + کنترل دستی پروکسی). اگر همچنان نشد، بخش پروکسی همین آموزش.

## ۲) پروکسی — وقتی میرور کافی نیست

برای دسترسی به سرویس‌هایی که کلاً از ایران محدودند (npm رسمی، API مدل‌ها، دانلودهای گیت‌هاب)، پروکسی استاندارد HTTP کار می‌کند — چه سرور شخصی شما خارج از کشور باشد چه سرویس داخلی provider پروکسی.

### متغیرهای محیطی (روش استاندارد)

```sh
export HTTP_PROXY=http://127.0.0.1:8118
export HTTPS_PROXY=http://127.0.0.1:8118
export NO_PROXY=localhost,127.0.0.1
```

قالب آماده در [`scripts/proxy-env.sh`](../scripts/proxy-env.sh) هست — آدرس و پورت را با سرویس خودتان جایگزین کنید. اکثر ابزارهای اکوسیستم Node (npm، pnpm، curl، گیت) این متغیرها را می‌فهمند.

### مخصوص npm

```sh
npm config set proxy http://127.0.0.1:8118
npm config set https-proxy http://127.0.0.1:8118
```

### مخصوص گیت (اگر کلون/push گیر کرد)

```sh
git config --global http.proxy http://127.0.0.1:8118
git config --global https.proxy http://127.0.0.1:8118
# حذف:
git config --global --unset http.proxy ; git config --global --unset https.proxy
```

⚠️ **تذکر امنیتی مهم:** همه ترافیک شما از پروکسی رد می‌شود؛ کلیدهای API و توکن گیت هم. از پروکسی فقط خودتان استفاده کنید، برای ارتباطات حساس (push گیت، کلید API) سرویس قابل‌اعتماد داشته باشید و هرگز کلیدها را در لاگ یا اسکرین‌شات پروکسی باقی نگذارید.

## ۳) DNS — وقتی همه‌چیز کند یا قطع است

اگر میرور و پروکسی هم اتصال شما را نجات نمی‌دهد، DNS عمومی سریع (مثل `178.22.122.100` یا `185.51.200.2` خدمات داخلی، یا `1.1.1.1`/`8.8.8.8` در صورت عبور آزاد) امتحان کنید. در ویندوز تنظیمات آداپتور، در لینوکس `/etc/resolv.conf` یا رابط شبکه. تست:

```sh
curl -I https://registry.npmjs.ir/     # باید 200 بدهد
nslookup registry.npmjs.org
```

## ۴) دسترسی به API مدل از ایران

مهم‌ترین تنگنای عملی: **سرویس API مدل‌ها (از جمله DeepSeek) از IP ایران معمولاً در دسترس نیست و پرداخت آن هم دشوار است.** سه راه‌حل واقعی:

1. **دروازه واسط (Relay/Gateway):** سرویس‌های واسطی که با پرداخت ریالی دسترسی OpenAI-compatible به مدل‌های مختلف می‌دهند. در dsh با «Custom model API» وصل می‌شوند — آموزش کامل و دقیق در [آموزش ۰۳](03-اولین-اجرای-شما.md). پروتکل را با سرویس‌تان چک کنید (`openai-completions` رایج‌ترین است).
2. **سرور واسط خارج از کشور:** یک VPS کوچک خارج از ایران که dsh را روی آن اجرا کنید و با SSH تونل (`ssh -L 3080:127.0.0.1:3080 user@vps`) رابط وب را روی سیستم خودتان باز کنید. این روش هم npm و هم API را بدون پروکسی محلی حل می‌کند.
3. **مدل محلی/داخلی سازگار با OpenAI:** اگر روی شبکه داخلی خودتان مدل میزبانی می‌کنید (هر دروازه‌ای با پروتکل OpenAI)، dsh مستقیماً به آن وصل می‌شود — کافی است Base URL و پروتکل درست را در Custom model API بدهید.

هر سه راه از مکانیزم رسمی پیکربندی ارائه‌دهنده dsh عبور می‌کنند؛ هیچ دست‌کاری در کد لازم نیست.

## ۵) کلون/push گیت‌هاب کند یا شکست می‌خورد

**علامت:** `git clone` گیر می‌کند، `Failed to connect to github.com`، یا push نیمه‌کاره می‌ماند.

**درمان‌ها به ترتیب:**

```sh
# ۱) پروکسی (بخش ۲)
git config --global http.proxy http://127.0.0.1:8118

# ۲) برای مخازن بزرگ: کلون کم‌عمق یا تکه‌ای
git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness.git
git clone --filter=blob:none https://github.com/...

# ۳) افزایش بافر HTTP برای pushهای بزرگ (مثل همین مخزن ۲۰۰ مگابایتی)
git config --global http.postBuffer 524288000

# ۴) در صورت قطعی مکرر: ادامه fetch ناتمام
git fetch --unshallow   # برای پر کردن کلون کم‌عمق بعداً
```

## ۶) خطاهای رایج اجرای dsh و معنی آن‌ها

| پیام خطا | معنی | راه‌حل |
|---|---|---|
| `node: command not found` | Node.js نصب نیست یا PATH قدیمی است | آموزش ۰۲ گام ۱؛ ترمینال جدید باز کنید |
| `npm ERR! code ETIMEDOUT` | شبکه به رجیستری | میرور ایران (بخش ۱) یا پروکسی (بخش ۲) |
| `EADDRINUSE :3080` | پروسه dsh قبلی هنوز زنده | پروسه قبلی را ببندید یا پورت را عوض کنید |
| `unsupported engine` | نسخه Node قدیمی | Node 20+ نصب کنید |
| مرورگر باز نمی‌شود | محیط بدون دسکتاپ (SSH) | `--no-open` و باز کردن دستی URL؛ یا تونل SSH |
| پاسخ مدل نمی‌آید / خطای 401 | کلید API نامعتبر یا مسیر مدل بسته | کلید را در Settings→Models چک کنید؛ راه‌حل بخش ۴ |
| ابزار web کار نمی‌کند | خروجی شبکه سرور بسته است | پروکسی روی سرور اجرای dsh، نه روی مرورگر شما |

## ۷) مسائل محلی‌سازی فارسی

- **فونت:** پورتال این مخزن فونت وزیرمتن را محلی حمل می‌کند (`portal/assets/fonts/`) — هیچ وابستگی به Google Fonts ندارد که در ایران مشکل‌ساز باشد. برای پروژه‌های خودتان هم همین الگو (فونت محلی) را توصیه می‌کنیم.
- **RTL:** مستندات Markdown این مخزن با `<div dir="rtl">` در گیت‌هاب راست‌به‌چپ رندر می‌شوند. در پورتال، `dir="rtl"` روی تگ `html` تنظیم شده.
- **اعداد و تاریخ:** ابزار نمونه «تقویم شمسی» در [`examples/jalali-plugin/`](../examples/jalali-plugin/) الگوی تبدیل تاریخ است؛ برای اعداد فارسی، تبدیل در لایه نمایش (render) انجام شود نه در داده، تا مدل هم بتواند بخواند.
- **ی/ک عربی و نیم‌فاصله:** اگر عامل فایل فارسی تولید کرد، بهتر است در پیام‌تان صریح بگویید «ی و ک فارسی و نیم‌فاصله استاندارد» — یا یک ابزار پاکسازی رشته فارسی به‌شکل پلاگین بنویسید (ایده خوب برای اولین پلاگین بومی!).

## ۸) خطاهای اجرای اسکریپت راه‌اندازی در ویندوز

دو خطای رایج هنگام اجرای `scripts/setup-iran` در ویندوز و راه‌حل قطعی هرکدام:

### الف) «running scripts is disabled on this system»

سیاست اجرای PowerShell در ویندوز به‌صورت پیش‌فرض روی `Restricted` است و جلوی اجرای هر اسکریپت `.ps1` را می‌گیرد. سه راه‌حل دارید — راه اول توصیه می‌شود چون سیاست فقط برای همان یک اجرا باز می‌شود:

```powershell
# راه ۱ — ساده‌ترین: لانچر بات خودِ مخزن (بای‌پس خودکار)
.\scripts\setup-iran.bat

# راه ۲ — فلگ Bypass فقط برای همین یک اجرا:
powershell -ExecutionPolicy Bypass -File scripts\setup-iran.ps1

# راه ۳ — فقط برای پنجره ترمینال جاری:
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup-iran.ps1
```

اگر می‌خواهید همیشه بدون این دردسر اسکریپت‌های محلی را اجرا کنید، یک‌بار برای کاربر خودتان روی `RemoteSigned` بگذارید — اسکریپت‌های محلی آزاد می‌شوند و اسکریپت‌های دانلودشده از اینترنت هنوز نیاز به امضای دیجیتال دارند:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### ب) «set: pipefail: invalid option name» هنگام اجرای bash

این خطا یعنی اسکریپت `.sh` را در ویندوز اجرا کرده‌اید. ماجرا از این قرار: گیت در ویندوز به‌صورت پیش‌فرض (`core.autocrlf=true`) هنگام clone انتهای خط‌ها را به CRLF تبدیل می‌کند و bash به‌جای گزینه `pipefail` عملاً `pipefail\r` می‌خواند و آن را نامعتبر می‌داند. دو نکته مهم:

- در ویندوز اصلاً از `setup-iran.sh` استفاده نکنید؛ نسخه ویندوزی همان کار `setup-iran.bat` یا `setup-iran.ps1` است.
- در WSL یا گیت‌بش اگر لازم شد `.sh` را اجرا کنید، یک‌بار انتهای خط‌ها را درست کنید:

```sh
sed -i 's/\r$//' scripts/setup-iran.sh
bash scripts/setup-iran.sh
```

از سوی دیگر، این مخزن حالا فایل `.gitattributes` دارد که تضمین می‌کند فایل‌های `.sh` همیشه با انتهای خط LF تحویل گرفته شوند. اگر مخزن را **قبل از این اصلاح** کلون کرده‌اید، پس از `git pull` یک‌بار این دستور را بزنید تا اسکریپت‌ها با تنظیم تازه بازنویسی شوند (یا کلاً دوباره clone کنید):

```sh
git pull
git checkout -- scripts/
```
