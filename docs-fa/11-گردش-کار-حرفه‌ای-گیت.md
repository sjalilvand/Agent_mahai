# آموزش ۱۱ — گردش کار حرفه‌ای گیت

راهنمای کامل مدیریت همین مخزن (Agent_mahai) روی سیستم خودتان: از نصب گیت و کلون اولیه تا شاخه‌سازی، commit منظم، push/pull و کار تیمی. در پایان، روش به‌روزرسانی پوشه `dsh/` از مخزن رسمی هم آمده است.

## ۱) نصب گیت

| سیستم‌عامل | روش نصب |
|---|---|
| ویندوز | نصب‌کننده از [git-scm.com](https://git-scm.com/download/win) یا `winget install Git.Git` |
| لینوکس (دبیان) | `sudo apt install git` |
| مک | `brew install git` یا ابزار خط فرمان Xcode |

تنظیمات اولیه یک‌باره (نام و ایمیل در هر commit ثبت می‌شود):

```sh
git config --global user.name "نام شما"
git config --global user.email "email@example.com"
git config --global init.defaultBranch main
```

## ۲) کلون مخزن روی سیستم خودتان

### روش الف — با توکن (سریع‌ترین)

```sh
git clone https://github.com/sjalilvand/Agent_mahai.git
```

اگر مخزن خصوصی شود یا برای push مشکل احراز هویت گرفتید، توکن را در URL بگذارید:

```sh
git clone https://<USERNAME>:<TOKEN>@github.com/sjalilvand/Agent_mahai.git
```

⚠️ **هشدار جدی امنیتی:** توکن در URL، در فایل `.git/config` هر مخزن و گاهی در لاگ‌ها باقی می‌ماند. هرگز: توکن را در کد، مستندات، اسکرین‌شات یا پیام عمومی نگذارید. توکنی که در گفتگو به اشتراک گذاشته شده را بعد از اتمام کار **حتماً از GitHub → Settings → Developer settings → Personal access tokens باطل (Revoke) کنید** و توکن تازه با محدوده حداقلی (فقط `repo`) بسازید. روش امن‌تر در بخش ۷.

### روش ب — با SSH (توصیه برای کار طولانی‌مدت)

```sh
# ساخت کلید
ssh-keygen -t ed25519 -C "email@example.com"
# کلید عمومی را در GitHub → Settings → SSH and GPG keys اضافه کنید
cat ~/.ssh/id_ed25519.pub

# تست
ssh -T git@github.com

# کلون
git clone git@github.com:sjalilvand/Agent_mahai.git
```

## ۴) چرخه روزمره: branch → edit → commit → push → pull

### شاخه‌سازی (Branch)

هرگز مستقیم روی `main` کار نکنید — حتی تنهایی. عادت حرفه‌ای: هر قابلیت/اصلاح یک شاخه.

```sh
git switch -c feature/portal-search        # ساخت و سوییچ
git switch main                             # برگشت به main
git branch -a                               # فهرست شاخه‌ها
```

قرارداد نام‌گذاری پیشنهادی این مخزن:

| پیشوند | کاربرد | مثال |
|---|---|---|
| `feature/` | قابلیت جدید | `feature/docs-arabic` |
| `fix/` | اصلاح باگ | `fix/npm-mirror-url` |
| `docs/` | تغییر مستندات | `docs/tutorial-04-update` |
| `update/` | به‌روزرسانی پوشه dsh | `update/dsh-v0.3.0` |

### ثبت تغییرات (Add / Commit)

```sh
git status                    # چه چیزی عوض شده؟
git diff                      # جزئیات تغییرات
git add docs-fa/              # صحنه‌سازی انتخابی (پیشنهادی)
git add .                     # یا همه‌چیز
git commit -m "docs: به‌روزرسانی آموزش ۰۴ با ابزارهای جدید"
```

قواعد commit خوب:

- **کوچک و موضوعی**: هر commit یک فکر. ۱۰۰ تغییر کوچک بهتر از ۱ تغییر غول‌آسا.
- **پیام معنادار**: قالب `type: خلاصه فارسی` — انواع رایج: `feat` (قابلیت)، `fix` (اصلاح)، `docs` (مستندات)، `refactor`، `update` (به‌روزرسانی dsh).
- هرگز کلید/توکن در commit — اگر اشتباهاً شد، فوراً توکن را باطل کنید و برای پاک‌سازی تاریخچه راهنمای گیت‌هاب را دنبال کنید.

### ارسال و دریافت (Push / Pull)

```sh
git push -u origin feature/portal-search   # اولین push شاخه جدید
git push                                    # دفعات بعد
git pull --rebase origin main               # دریافت آخرین تغییرات + بازنویسی تمیز
```

`pull` را **قبل از شروع کار** و **قبل از push** بزنید تا تعارض‌ها زود و کوچک بمانند. پرچم `--rebase` تاریخچه خطی و خوانا نگه می‌دارد.

## ۵) حل تعارض (Merge Conflict) بدون استرس

تعارض وقتی است که دو طرف یک خط را عوض کرده باشند:

```sh
git pull --rebase origin main
# CONFLICT در فایل X
```

۱. فایل متعارض را باز کنید — بلوک‌های `<<<<<<< HEAD` / `=======` / `>>>>>>>` را می‌بینید.
۲. نسخه نهایی درست را دستی بنویسید (ترکیب یا انتخاب) و نشانه‌ها را حذف کنید.
۳.

```sh
git add X
git rebase --continue       # یا در merge ساده: git commit
# فرار در وسط راه: git rebase --abort
```

در VS Code دکمه‌های «Accept Current / Incoming / Both» همین کار را با کلیک انجام می‌دهند.

## ۶) کار تیمی چندنفره — الگوی پیشنهادی

برای تیم‌های ۲ تا ۱۰ نفره روی این مخزن:

1. **محافظت از main**: در گیت‌هاب → Settings → Branches → Branch protection: مستقیم push به main ممنوع، حداقل یک review الزام.
2. **Pull Request برای همه تغییرات**: `feature/...` را push کنید، در گیت‌هاب PR باز کنید، یک همکار مرور و تأیید کند، سپس Merge (ترجیحاً Squash merge برای تاریخچه تمیز).
3. **پس از merge**: شاخه را حذف کنید (`git branch -d ...` و `git push origin --delete ...`) و محلی را sync کنید:

```sh
git switch main
git pull --rebase origin main
git remote prune origin
```

4. **Issues و Projects**: وظایف را در Issues ثبت کنید؛ در پیام commit از `#شماره-ایسو` استفاده کنید تا اتوماتیک لینک شود.
5. **تگ انتشار**: هر بار پورتال/مستندات نسخه پایدار شد: `git tag -a v1.0.0 -m "نسخه ۱.۰.۰" && git push --tags`

## ۷) مدیریت امن توکن — روش‌های درست

| روش | امنیت | کاربرد |
|---|---|---|
| URL با توکن | ضعیف — توکن در config می‌ماند | فقط تست موقت |
| Git Credential Manager | خوب — ویندوز/مک خودکار ذخیره می‌کند | کاربر عادی |
| SSH key | بهترین — هیچ توکنی جابه‌جا نمی‌شود | کار طولانی‌مدت (توصیه) |
| Fine-grained PAT | خوب — فقط یک مخزن، فقط دسترسی لازم | اتوماسیون/CI |

همیشه: حداقل محدوده دسترسی (`Contents: Read and Write` کافی است)، تاریخ انقضا کوتاه، و باطل‌سازی فوری بعد از نشت.

## ۸) به‌روزرسانی پوشه `dsh/` از مخزن رسمی

وقتی پروژه اصلی نسخه جدید داد، لایه بومی‌سازی شما را حفظ کنید و فقط سورس را عوض کنید:

```sh
# روی شاخه جدید
git switch -c update/dsh-latest

# سورس قدیمی را حذف و سورس تازه را جایگزین کنید
rm -rf dsh
git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness.git dsh-tmp
rm -rf dsh-tmp/.git
mv dsh-tmp dsh

# بازبینی: تغییرات ناسازگار را با آموزش ۰۷ چک کنید
git add dsh
git commit -m "update: همگام‌سازی سورس dsh با مخزن رسمی"
git push -u origin update/dsh-latest
# سپس PR و مرور و merge
```

قبل از merge حتماً: `pnpm install && pnpm run build && pnpm dsh web` را تست کنید تا مطمئن شوید نسخه تازه با مستندات فارسی شما (مثلاً شماره پورت یا نام ابزارها) همچنان سازگار است.

## ۹) جدول سریع فرمان‌ها

| کار | فرمان |
|---|---|
| کلون | `git clone <url>` |
| شاخه جدید | `git switch -c feature/x` |
| وضعیت | `git status` |
| صحنه‌سازی | `git add .` |
| ثبت | `git commit -m "msg"` |
| ارسال اول | `git push -u origin branch` |
| دریافت | `git pull --rebase origin main` |
| تاریخچه | `git log --oneline --graph -20` |
| برگشت تغییر محلی | `git restore <file>` |
| برگشت commit آخر | `git revert HEAD` |
| stash موقت | `git stash` / `git stash pop` |
| حذف شاخه | `git branch -d branch` |
