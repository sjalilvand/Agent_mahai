ساخت پلاگین اختصاصی

معماری «همه‌چیز پلاگین است» یعنی ابزار بعدی، ایده خود شماست — از سلام‌دنیا تا تقویم شمسی.

محتوای این صفحه

سه مفهوم کلیدی پلاگین سلام‌دنیا اولین ابزار نمونه: تقویم شمسی چک‌لیست کیفیت انتشار

سه مفهوم کلیدی

🧩

پلاگین

ماژولی با تابع apply که به زمین Cordis وصل می‌شود و قابلیت (ابزار/سرویس/رابط) اضافه می‌کند.

📦

باندل

بسته npm با کلید dsh.bundle در مانیفست — یک فایل patch حمل می‌کند. چیزی که شما توزیع می‌کنید.

⚙️

پروفایل

ترکیب باندل‌ها در $DSH_HOME/profiles — چیزی که کاربر با dsh --profile بوت می‌کند.

پلاگین سلام‌دنیا

ساختار پوشه:

hello-plugin/ ├── package.json # مانیفست باندل (dsh.bundle) ├── index.js # نقطه ورود پلاگین └── cordis.patch.yml # لایه پیکربندی
// package.json { "name": "dsh-hello-plugin", "version": "0.1.0", "type": "module", "main": "index.js", "files": ["index.js", "cordis.patch.yml"], "dsh": { "bundle": { "patch": "./cordis.patch.yml" } } }
// cordis.patch.yml - insert: - id: hello name: dsh-hello-plugin

اجرای محلی با لایه اضافی:

pnpm dsh web --patch ./hello-plugin/cordis.patch.yml

اولین ابزار مدل‌محور

با defineTool ابزار تعریف می‌کنید؛ اعتبارسنجی ورودی خودکار از روی پارامترها ساخته می‌شود:

import type { Context } from '@deepseek-ai/cordis' import { defineTool } from '@deepseek-ai/dsh-tools' export const name = 'greet-tool' export const inject = ['tools'] // تزریق وابستگی: رجیستری ابزار export function apply(ctx: Context) { ctx.tools.register(defineTool({ name: 'greet', description: 'به یک نفر سلام می‌کند.', parameters: { name: { type: 'string', required: true, description: 'نام فرد' }, }, output: { schema: { type: 'string' }, render: (_args, value) => [{ type: 'text', text: value }], }, async execute(args) { return `سلام، ${args.name}!` }, })) }
💡
سه نکته کلیدی: ۱) inject ترتیب بارگذاری را تضمین می‌کند ۲) defineTool ورودی‌ها را infer و validate می‌کند ۳) خروجی متعارف و رندر جداست — یک ابزار، نسخه‌های درست برای مدل و UI.

نمونه بومی: تقویم شمسی 🇮🇷

پلاگین کامل و آماده اجرا در examples/jalali-plugin/ مخزن — ابزار date_convert با الگوریتم استاندارد جلالی و بدون وابستگی خارجی:

# اجرا از ریشه مخزن (بعد از build سورس) cd dsh pnpm dsh web --patch ../examples/jalali-plugin/cordis.patch.yml

سپس در مکالمه بپرسید: «۲۵ اسفند ۱۴۰۴ چه روزی از سال میلادی است؟» — عامل ابزار را صدا می‌زند و جواب دقیق می‌دهد.

ایده‌های بومی‌سازی دیگر

• تبدیل اعداد فارسی/انگلیسی
• تعطیلات رسمی و مناسبت‌های ایران
• اعتبارسنجی کد ملی
• پاکسازی رشته فارسی (ی/ک، نیم‌فاصله)

لایه‌بندی حرفه‌ای

پلاگین بزرگ شد؟ الگوی رسمی سه‌بخشی: تعریف سرویس (قرارداد) + ارائه‌دهنده سرویس (پیاده‌سازی قابل تعویض) + مصرف‌کننده — همان الگویی که خود dsh استفاده می‌کند.

چک‌لیست کیفیت پلاگین

موردچرا مهم است
نام ابزار کوتاه و یکتا (snake_case)مدل راحت‌تر انتخاب می‌کند
description دقیق و جهت‌دهندهمدل با همین متن تصمیم به فراخوانی می‌گیرد
پارامترهای required حداقلیهر پارامتر اضافی = یک نقطه خطا
خطاها به‌شکل پیام قابل‌فهممدل می‌تواند خودش اصلاح کند
اعلام engines.dshمحافظت سازگاری نسخه — نصب ناسازگار بسته می‌شود
files دقیق در package.jsonبسته تمیز، بدون کلید و فایل زائد

انتشار

npm pack # ساخت تاربال نهایی dsh plugin --profile web add ./dsh-*.tgz # تست نصب محلی npm publish --registry https://registry.npmjs.org/ # انتشار (از میرور منتشر نکنید!)

۱) npm

بسته استاندارد npm — برای انتشار حتماً رجیستری رسمی، نه میرور ایرانی.

۲) موضوع dsh-plugin

به مخزن گیت‌هاب پلاگین، موضوع (topic) dsh-plugin را اضافه کنید تا کشف‌پذیر شوید.

۳) بازار پلاگین

ایندکس‌های بازار با plugin_market مرور و با plugin_manager نصب می‌شوند؛ ابزار plugin-market-generator برای ساخت ایندکس خصوصی.
