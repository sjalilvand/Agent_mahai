رفع مشکلات رایج در ایران

میرور، پروکسی، DNS، دسترسی به API مدل و خطاهای رایج — روی هر سؤال کلیک کنید.

npx خطای 403 یا Timeout می‌دهد — چه کنم؟

رجیستری رسمی npm برای IPهای ایران گاهی محدود است. میرور ایرانی تنظیم کنید:

npm config set registry https://registry.npmjs.ir/ npm ping npx @deepseek-ai/dsh web

یا اسکریپت آماره: bash scripts/setup-iran.sh (لینوکس/مک) — .\scripts\setup-iran.bat (ویندوز، بدون دردسر ExecutionPolicy).

ویندوز می‌گوید «running scripts is disabled» — چه کنم؟

سیاست اجرای PowerShell به‌صورت پیش‌فرض روی Restricted است و اجرای اسکریپت را قفل می‌کند. ساده‌ترین راه، لانچر بات خودِ مخزن است که بای‌پس را خودش انجام می‌دهد:

.\scripts\setup-iran.bat

یا فلگ Bypass فقط برای همین یک اجرا:

powershell -ExecutionPolicy Bypass -File scripts\setup-iran.ps1

برای همیشه (کاربر فعلی): Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

bash می‌گوید «set: pipefail: invalid option name» — مشکل چیست؟

اسکریپت .sh را در ویندوز اجرا کرده‌اید (یا انتهای خط‌ها CRLF شده). در ویندوز فقط از setup-iran.bat یا setup-iran.ps1 استفاده کنید. در WSL یک‌بار انتهای خط‌ها را درست کنید:

sed -i 's/\r$//' scripts/setup-iran.sh bash scripts/setup-iran.sh

نسخه‌های جدید مخزن با .gitattributes این مشکل را برای کلون‌های تازه حل کرده‌اند.

میرور ایران npm کار می‌کند ولی بسته dsh را پیدا نمی‌کند — چه کنم؟

میرور ایران برخی بسته‌های scoped (مثل @deepseek-ai/dsh) را کامل پوشش نمی‌دهد — npm ping سالم است ولی خود بسته نیست. اول تست کنید:

npm view @deepseek-ai/dsh version

اگر به‌جای نسخه، خطا داد، میرور چینی را تنظیم کنید — از ایران قابل دسترس و سریع است:

npm config set registry https://registry.npmmirror.com/ npm view @deepseek-ai/dsh version # باید نسخه چاپ شود npx @deepseek-ai/dsh web

اسکریپت setup-iran نسخه‌های جدید مخزن، این بررسی و سوییچ را خودکار انجام می‌دهد. راه نهایی: نصب از سورس محلی dsh/ همین مخزن (آموزش ۰۲).

مرورگر روی 127.0.0.1:3080 می‌گوید ERR_CONNECTION_REFUSED — چرا؟

یعنی هنوز هیچ سروری روی پورت ۳۰۸۰ گوش نمی‌دهد. دو حالت شایع دارد:

۱) اولین اجرا هنوز در حال دانلود است: npx ابتدا بسته dsh را دانلود و کش می‌کند — بسته به شبکه چند دقیقه طول می‌کشد (در ترمینال نوار چرخان می‌بینید). تا ظاهر شدن لاگ گوش‌دادن سرور صبر کنید، بعد در مرورگر Reload بزنید.

۲) دانلود شکست خورده: اگر ترمینال به prompt برگشت و خطا داد. تست کنید سرور واقعاً بالا آمده یا نه:

# ویندوز (PowerShell) Get-NetTCPConnection -LocalPort 3080 -ErrorAction SilentlyContinue # لینوکس / مک ss -tlnp | grep 3080

خروجی خالی = سرور اجرا نشده؛ معمولاً مشکل از دسترسی به بسته است (سؤال قبل را ببینید).

قبلاً کار می‌کرد ولی الان دوباره سایت بالا نمی‌آید — پنجره ترمینال را بسته‌ام یا Ctrl+C زده‌ام!

این طبیعی‌ترین حالت است: پنجرهٔ ترمینالی که setup-iran در آن اجرا شده، خودِ سرور است. با بستن پنجره یا فشردن Ctrl+C (پیام Terminate batch job (Y/N)?) موتور خاموش می‌شود و مرورگر دیگر به پورت ۳۰۸۰ دسترسی ندارد. راه‌حل فقط یک خط است:

.\scripts\setup-iran.bat

و بعد پنجره را باز نگه دارید (می‌توانید minimize کنید). سپس آدرس کامل چاپ‌شده در ترمینال — یعنی خط dsh web: http://127.0.0.1:3080/?token=... — را در مرورگر باز کنید (هر بار اجرا توکن جدید می‌سازد) و با Ctrl+F5 تازه‌سازی کنید. برای بررسی زنده بودن سرور:

Get-NetTCPConnection -LocalPort 3080 -ErrorAction SilentlyContinue
ℹ️
پوستهٔ فارسی ماه‌ای روی کش npx اعمال می‌شود و با اجرای مجدد سرور می‌ماند؛ فقط اگر dsh به‌روزرسانی شود و رابط انگلیسی شود، یک‌بار powershell -ExecutionPolicy Bypass -File scripts\patch-mahai-ui.ps1 را بزنید. نسخه‌های جدید setup-iran این پچ را خودکار و قبل از هر اجرا اعمال می‌کنند.
صفحه فقط می‌گوید «dsh web authentication required; reopen the URL printed by dsh web» — چرا؟

نگران نباشید — سرور شما دارد کار می‌کند! این صفحه یعنی آدرس را بدون توکن باز کرده‌اید. سرور ماه‌ای به‌دلایل امنیتی بدون کلید توکن هیچ چیزی نشان نمی‌دهد. اگر در نوار آدرس فقط 127.0.0.1:3080 را تایپ کنید، یا از بوکمارک/تب قدیمیِ مربوط به اجرای قبلی بروید (توکن‌های قدیمی با هر اجرای مجدد سرور بی‌اعتبار می‌شوند)، دقیقاً همین صفحهٔ انگلیسی را می‌بینید — این خرابی پوسته نیست و ربطی به فارسی‌سازی ندارد.

راه‌حل سه قدمی:

۱) به پنجرهٔ ترمینالِ در حال اجرا بروید (همان پنجره‌ای که setup-iran.bat در آن باز است و باید باز بماند) و خطی شبیه زیر را پیدا کنید:

dsh web: http://127.0.0.1:3080/?token=Nb-vuDb7sDT2Yi_...

۲) کل همین خط را — از http تا انتهای توکن، شامل ?token= — با موس انتخاب و کپی کنید (در Windows Terminal با Ctrl+Shift+C، در کنسول کلاسیک بعد از انتخاب با موس، Enter یا راست‌کلیک). دقت کنید در ترمینال Ctrl+C نزنید — این کلید سرور را خاموش می‌کند!

۳) در مرورگر (ترجیحاً پنجرهٔ ناشناس/InPrivate برای دور زدن کش) در نوار آدرس بچسبانید و Enter بزنید، سپس Ctrl+F5 بزنید. برند «پوستهٔ فارسی ۹» در سایدبار باید دیده شود.

ℹ️
از نسخهٔ جدید راه‌انداز (git pull بزنید)، setup-iran.bat خودش آدرس کامل توکن‌دار را به‌محض بالا آمدن سرور در کلیپ‌بورد کپی می‌کند و با کادر زرد نمایش می‌دهد — کافی است در مرورگر Ctrl+V بزنید.
⚠️
اگر پنجرهٔ ترمینال را بسته‌اید یا Ctrl+C زده‌اید، سرور خاموش شده و توکن فعلی مرده است؛ دوباره .\scripts\setup-iran.bat اجرا کنید و از خط dsh web: جدید استفاده کنید.
در ترمینال خط «[deepseek-account] request failed … status: 403» تکرار می‌شود — مشکلی است؟

خیر — اگر گفت‌وگوها پاسخ می‌گیرند، این خط‌ها بی‌خطرند و می‌توانید نادیده‌شان بگیرید. معنای آن‌ها این است: موتور ماه‌ای دوره‌ای وضعیت ورود حساب DeepSeek را از سرور دیپ‌سیک (/auth-api/v0/users/current) بررسی می‌کند. پاسخ 403 یعنی «دسترسی داده نشد» و دو علت رایج دارد: (۱) فعلاً با حساب DeepSeek وارد نشده‌اید (مثلاً فقط کلید API دارید یا از حالت آزمایشی استفاده می‌کنید)، یا (۲) سرور احراز هویت دیپ‌سیک به درخواست‌های شبکهٔ ایران پاسخ منفی می‌دهد — در حالی که خط دیگری از همان ترمینال یعنی model listing … loaded 2 model(s) نشان می‌دهد اتصال به سرویس مدل‌ها برقرار است.

چه زمانی باید جدی بگیرید؟ فقط وقتی که ارسال پیام پاسخ نمی‌گیرد یا برنامه پیام «مدل در دسترس نیست. لطفاً وارد شوید» می‌دهد. در آن صورت یکی از این دو راه را بروید: در خود برنامه از منوی حساب گزینهٔ ورود را بزنید و وارد حساب DeepSeek شوید، یا از منوی حساب گزینهٔ افزودن کلید API را انتخاب و کلید خود را از پلتفرم دیپ‌سیک وارد کنید. اگر شبکهٔ شما برای دسترسی به سرویس‌های خارجی به پروکسی نیاز دارد، طبق پرسش «تنظیم پروکسی» در همین صفحه عمل کنید — این خط‌ها سپس از بین می‌روند.

چطور پروکسی را برای همه ابزارها تنظیم کنم؟

متغیرهای محیطی استاندارد HTTP — اکثر ابزارها (npm، pnpm، گیت، curl) می‌فهمند:

export HTTP_PROXY=http://127.0.0.1:8118 export HTTPS_PROXY=http://127.0.0.1:8118 export NO_PROXY=localhost,127.0.0.1

مخصوص npm:

npm config set proxy http://127.0.0.1:8118 npm config set https-proxy http://127.0.0.1:8118

مخصوص گیت:

git config --global http.proxy http://127.0.0.1:8118
⚠️
همه ترافیک (از جمله کلیدهای API) از پروکسی رد می‌شود — از سرویس قابل‌اعتماد استفاده کنید.
دسترسی به API مدل از ایران؟ (مهم‌ترین سؤال)

سرویس API مدل‌ها از IP ایران معمولاً بسته است و پرداخت هم دشوار. سه راه‌حل واقعی:

۱. دروازه واسط ایرانی: سرویس‌های واسط با پرداخت ریالی دسترسی OpenAI-compatible می‌دهند. در dsh: Settings → Models → Add model provider → Custom model API — Base URL و پروتکل (معمولاً openai-completions) و کلید را بدهید.

۲. سرور واسط خارج از کشور: dsh را روی یک VPS کوچک اجرا کنید و با تونل SSH رابط وب را باز کنید:

ssh -L 3080:127.0.0.1:3080 user@your-vps # سپس در مرورگر خودتان: http://127.0.0.1:3080

۳. مدل داخلی: هر دروازه داخلی با پروتکل OpenAI مستقیماً وصل می‌شود.

هر سه راه از پیکربندی رسمی dsh عبور می‌کنند — بدون دست‌کاری کد.

git clone یا push کند است یا قطع می‌شود
# ۱) پروکسی git config --global http.proxy http://127.0.0.1:8118 # ۲) برای مخازن بزرگ: کلون کم‌عمق git clone --depth 1 https://github.com/... # ۳) برای pushهای بزرگ (مثل این مخزن ~۲۰۰MB): git config --global http.postBuffer 524288000
EADDRINUSE :3080 — پورت اشغال است

پروسه قبلی dsh هنوز زنده است. ببندیدش:

# لینوکس/مک lsof -i :3080 kill <PID> # ویندوز netstat -ano | findstr :3080 taskkill /PID <PID> /F
پاسخ مدل نمی‌آید یا خطای 401 می‌گیرم

کلید API نامعتبر است یا مسیر مدل بسته. در Settings → Models کلید را چک کنید. کلیدها فقط‌نوشتنی‌اند — برای تغییر، مقدار جدید وارد و ذخیره کنید. اگر از دروازه واسط استفاده می‌کنید، Base URL و پروتکل را با مستندات سرویس‌تان تطبیق دهید.

برخی بسته‌ها از میرور ایرانی پیدا نمی‌شوند

میرورها با تأخیر به‌روز می‌شوند. موقتاً به رسمی برگردید با پروکسی:

npm config set registry https://registry.npmjs.org/ export HTTPS_PROXY=http://127.0.0.1:8118 npx @deepseek-ai/dsh web
فارسی و RTL — فونت، اعداد، نیم‌فاصله؟

پورتال این مخزن فونت وزیرمتن را محلی حمل می‌کند (بدون Google Fonts). برای پروژه‌های خودتان هم فونت محلی را توصیه می‌کنیم. اگر عامل فایل فارسی تولید کرد، در پیام‌تان صریح بگویید «ی و ک فارسی و نیم‌فاصله استاندارد» — یا یک ابزار پاکسازی رشته فارسی به‌شکل پلاگین بسازید (الگو در صفحه پلاگین‌نویسی).

رابط وب انگلیسی است — چطور فارسی و آبی (ماه‌ای) شود؟

پوستهٔ ماه‌ای را روی رابط اعمال کنید — فارسی‌سازی کامل منوها (بیش از ۸۵۰ رشته + ۹۰ الگو)، فونت وزیرمتن، تم آبی لوگو، ارم و نشان شرکت در سایدبار و صفحهٔ آغازین:

# لینوکس / مک / WSL bash scripts/patch-mahai-ui.sh # ویندوز powershell -ExecutionPolicy Bypass -File scripts\patch-mahai-ui.ps1

سپس مرورگر را با Ctrl+F5 تازه‌سازی کنید. اگر پیام «هیچ نصبی پیدا نشد» دیدید، یعنی dsh هنوز دانلود نشده؛ یک‌بار npx @deepseek-ai/dsh web را اجرا کنید تا دانلود شود، سپس پچ را بزنید. اسکریپت setup-iran این گام را به‌صورت خودکار انجام می‌دهد. اگر بعد از به‌روزرسانی dsh رابط دوباره انگلیسی شد، همان دستور را تکرار کنید — اجرای مکرر بی‌ضرر است.

صفحه نصفه می‌آید / ستون‌ها از لبه بریده‌اند / سایدبار دیده نمی‌شود

اگر پوستهٔ فارسی نسخهٔ ۸ یا قدیمی‌تر را دارید، علت این است که آن نسخه‌ها dir="rtl" را روی کل صفحه می‌گذاشتند و چیدمان اپ (که برای چپ‌به‌راست طراحی شده) آینه می‌شد: سایدبار بیرون از صفحه می‌افتاد و ستون‌ها بریده می‌شدند. در نسخهٔ ۹ چیدمان دست‌نخورده می‌ماند و فقط متن‌ها فارسی می‌شوند. رفع:

git pull powershell -ExecutionPolicy Bypass -File scripts\patch-mahai-ui.ps1

سپس سرور را دوباره اجرا کنید و در مرورگر Ctrl+F5 بزنید. برند سایدبار باید «پوستهٔ فارسی ۹» را نشان دهد. اگر هنوز مشکل داشتید، یک‌بار Ctrl+Shift+Del (پاک کردن کش) یا پنجرهٔ ناشناس را امتحان کنید.

الزامات نسخه (engines.dsh) برآورده نمی‌شود

باندل پلاگین با نسخه dsh شما سازگار نیست — نصب به‌صورت حفاظتی بسته می‌شود. dsh را به‌روز کنید یا نسخه سازگار پلاگین را نصب کنید. «معافیت نسخه» با ریسک خرابی همراه است؛ فقط با آگاهی کامل.
